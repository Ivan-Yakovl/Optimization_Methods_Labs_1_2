```text
N = 28; Q = 1; Y = 26

seed = 10000 + 100*Q + N = 10128
```

В каждой папке собственный README и полный самостоятельный комплект. Для чтения готовых отчётов установка Python не требуется.

## Состав комплекта

В `lab1/` и `lab2/` находятся:

- `Отчёт.pdf`, `Отчёт.md` — постановка, формальная модель и единицы, допущения, решение, сценарии, независимая проверка и практические выводы;
- `main.py` — загрузка и генерация данных, построение модели, проверка и эксперименты;
- `common.py` — интерфейс открытого солвера HiGHS и файловая отчётность;
- `reporting.py` — формирование отчётов из результатов запуска;
- `data.json`, `metadata.json`, `requirements.txt` — данные, индивидуальный вариант и закреплённые версии;
- `results/` — планы CSV, данные сценариев, логи HiGHS, LP-файлы моделей, проверки JSON/CSV и рисунки;
- `test_validation.py` — регрессионные проверки;
- `К_защите.md` — пояснения к вопросам защиты.

Числовые данные синтетические. Процедуры генерации и seed описаны в отчётах и исходном коде. Все обязательные эксперименты основных работ выполнены. Дополнительные задания и задания со звёздочкой в комплект не входят.

## Установка и полный запуск

Требуется **Python 3.12**; при выполнении использован Python 3.12.14. Обе работы используют одинаковые закреплённые зависимости. Следующие команды выполняются из корня клонированного репозитория.

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
..venvScriptspython.exe -m pip install -r lab1
equirements.txt
..venvScriptspython.exe lab1main.py
..venvScriptspython.exe lab2main.py
```

Linux и macOS при установленном Python 3.12:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r lab1/requirements.txt
.venv/bin/python lab1/main.py
.venv/bin/python lab2/main.py
```

Каждая команда `main.py` решает все задачи соответствующей работы, проверяет решения, сохраняет результаты и рисунки и обновляет PDF и Markdown. Работа с HiGHS выполняется в одном потоке, presolve включён, допуск независимой проверки — `1e-7`. Запуск не зависит от рабочего каталога: файлы ищутся относительно `main.py`.

Для восстановления исходных данных добавьте `--regenerate-data` к запуску нужной работы. Данные и модель хранятся раздельно. Обычный повторный запуск перезаписывает результаты и отчёты, но не изменяет `data.json`.

## Проверка корректности

В Windows PowerShell из корня:

```powershell
..venvScriptspython.exe lab1	est_validation.py
..venvScriptspython.exe -O lab1	est_validation.py
..venvScriptspython.exe lab2	est_validation.py
..venvScriptspython.exe -O lab2	est_validation.py
..venvScriptspython.exe -m pip check
```

Для Linux/macOS замените путь интерпретатора на `.venv/bin/python` и обратные слеши на `/`.

Независимые проверки не обращаются к объекту солвера и не используют матрицу построения модели: ограничения и цель заново вычисляются из предметных данных. Проверены 7 оптимальных решений ЛР 1, 13 оптимальных решений и 5 жадных планов ЛР 2. Все статусы оптимальных расчётов — `Optimal`; все независимые проверки пройдены. У каждой работы 8 регрессионных тестов, пройденных в обычном режиме и с `-O`.

Времена в CSV относятся к фактическому запуску и могут измениться при повторении. При альтернативных оптимумах солвер может выбрать другой равноценный план. Округлённые числа из PDF не заменяют полную точность CSV/JSON.
