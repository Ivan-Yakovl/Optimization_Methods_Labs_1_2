# Лабораторная работа № 1

ЛП-модель раскроя листового материала. Яковлев Иван, Б24-517, № 28, осенний семестр 2026.

Вариант: 1 + ((17·28 + 7·1 + 26) mod 20) = 10. Seed: 10128.

База: **79,525 м²** использованного листового материала, **4,875 м²** отходов. Модель: 4 типа листов, 5 позиций заказа, 753 схемы раскроя.

## Установка и запуск

Требуется Python 3.12 (при выполнении использован 3.12.14). Открыть терминал **в этой папке**.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

После установки запуск всех обязательных расчётов, проверок, рисунков и формирования отчёта выполняется одной командой `python main.py` в активированном окружении. Интернет нужен только для первоначальной установки зависимостей. Пример с полным путём к интерпретатору приведён выше; активация окружения не требуется.

Восстановление исходных данных и полный запуск:

```powershell
.\.venv\Scripts\python.exe main.py --regenerate-data
```

Для повторного оформления уже имеющихся результатов без решения моделей:

```powershell
.\.venv\Scripts\python.exe reporting.py
```

При запуске перезаписываются только созданные программой результаты и отчёты в этой папке. Отдельные папки работ независимы друг от друга; общих внешних исходников нет.

## Интерпретация

Основные расчёты завершены со статусом Optimal. Для MILP окончательный gap относится к доказательству оптимальности текущей целочисленной задачи; зазор MILP/LP отдельно вычисляется по релаксации. Синтетические данные не являются измерениями реального предприятия.

Время в CSV — фактическое время решения на компьютере выполнения; при повторном запуске оно изменится. При нескольких оптимумах могут различаться планы с одинаковым значением цели. Отчёт при запуске формируется заново по полученным числам.

Независимая проверка пересчитывает ограничения из предметных данных и вектора, без обращения к объекту солвера и без использования матрицы build_model. При нарушении допуска или ошибке цели программа останавливается. При статусе, отличном от Optimal, обычное оформление также останавливается.

## Проверка корректности и воспроизводимости

Проверки остаются активными при `python -O`. Не допускаются NaN, бесконечности, векторы неправильной длины и нарушение ограничений. Вызовы настройки и передачи модели в HiGHS выполняются независимо от режима оптимизации Python.

```powershell
.\.venv\Scripts\python.exe test_validation.py
.\.venv\Scripts\python.exe -O test_validation.py
.\.venv\Scripts\python.exe -m pip check
```

В `test_validation.py` восемь содержательных проверок: исходный план; передача непустой модели солверу; NaN/Inf; неверная длина; ошибка цели; отрицательная переменная; нарушение предметного ограничения; целочисленность, геометрия или баланс в зависимости от работы. Ошибочные планы проверяются во временной папке и не попадают в сдаваемые результаты.

Комплект проверен в отдельном окружении, установленном из requirements.txt; выполнены полные программы и регрессионные тесты. Установка зависимостей и pip check завершились успешно. Файл `К_защите.md` содержит краткие пояснения к основным вопросам методички.

Все 7 решений, включая четыре опыта изменения запасов для проверки теневых цен, независимо проверены. Спрос, запасы, геометрия и единицы указаны в отчёте. В CSV приведены все 753 переменные схем; рисунок показывает ненулевые схемы.
